## Deferred from: code review of story-1-1 (2026-08-04)

- Email send failures (verification/reset) are silently swallowed — sign-up and forgot-password always report success even when Resend never actually sent the email, with no retry/alerting/observability (better-auth's `runInBackgroundOrAwait` only logs and swallows the failure). Deferred: no logging/alerting infra exists in this project yet; accepted for now rather than scoping a partial fix. [lib/auth/config.ts, lib/auth/send-email.tsx]
- `EMAIL_FROM` defaults to Resend's sandbox sender (`onboarding@resend.dev`), which can only deliver to the Resend account owner's own inbox — every real user's email will silently fail if this ships to production without a verified custom domain. Deferred: no verified custom sending domain set up yet; treat as a pre-launch checklist item. [.env.example, lib/auth/send-email.tsx]
- Expired/reused email-verification links redirect to the locale home page with `?error=` unread — no feedback, no "resend verification" affordance. Fix touches `app/[locale]/(marketing)/page.tsx`, a Story 1.0 file outside Story 1.1's task list. [app/[locale]/(marketing)/page.tsx]
- Concurrent identical-case duplicate sign-ups can surface as a generic error without the sign-in link, because better-auth's own `createUser` catch-block collapses any DB conflict to `FAILED_TO_CREATE_USER` rather than `USER_ALREADY_EXISTS_USE_ANOTHER_EMAIL` (verified in `better-auth`'s `sign-up.mjs`). Pre-existing gap in better-auth's own error mapping — affects same-case races too, not introduced by Story 1.1's case-insensitive index specifically. [lib/auth/config.ts]
- AR/EN locale-detection parity for transactional emails wasn't exercised end-to-end through the real `Referer`-based detection path during manual QA — only verified via direct template rendering with a `locale` prop and separately verified `/ar` UI pages. Re-verify once the `NEXT_LOCALE`-cookie patch (see story 1.1 Review Findings) lands. [lib/auth/locale.ts]
