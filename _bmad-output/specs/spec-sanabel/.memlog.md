- (decision) Why: a vision to realize — Ahmed's personal, non-commercial conviction that learning to code should be free permanently, with no paywall/ads/monetization pressure, launching as a real if modest public bar (friends/community first) for two named personas: Yousef (instructor) and Lina (learner).
- (capability) CAP-1 Accounts & Authentication — intent: any visitor signs up/in via email+password or Google/GitHub and holds Learner/Instructor/Admin role flags on one account, Instructor status admin-granted only (FR-1..FR-5); success: new signup verifies email, social login on the same verified email merges to one account, an Instructor-granted account sees authoring surfaces a plain Learner never does.
- (capability) CAP-2 Course Authoring — intent: an Instructor builds a Course from a minimal start (title/description/category) into a nested Module→Lesson outline with drag-reorder, 5 lesson types (Video/Text/PDF/Quiz/Interactive Code Exercise), continuous autosave, learner-accurate preview, publish with visibility+category, post-publish edits, and per-lesson analytics (FR-6..FR-16); success: UJ-1 Yousef goes from empty dashboard to a published Unlisted multi-lesson course with all 5 lesson types without losing work, then sees view/completion counts per lesson.
- (capability) CAP-3 Course Discovery — intent: any visitor browses/searches Public courses by category and views a Course's public detail page (outline titles, instructor bio, ratings) pre-signup; a signed-in Learner enrolls in any reachable course at no cost (FR-17..FR-19); success: UJ-2 Lina reaches a course via shared link, reviews it signed-out, then enrolls after lightweight signup.
- (capability) CAP-4 Learning Experience — intent: an enrolled Learner sees overall + per-lesson progress, always resumes exactly where left off via 'Continue', and gets immediate graded feedback with explanatory hints on quizzes and interactive code exercises (FR-20..FR-25); success: a Learner returning weeks later resumes at the exact last incomplete lesson; a wrong quiz/exercise answer returns an explanatory hint, never a bare 'incorrect'.
- (capability) CAP-5 Certificates — intent: on completing all required lessons/quizzes/exercises in a Course, a Learner receives a downloadable certificate (name, course, instructor, date) and a rating prompt (FR-26..FR-27); success: completion produces a certificate download plus a same-session rating prompt; a certificate already issued survives later additions to the course (FR-15).
- (capability) CAP-6 Discussion — intent: a signed-in Learner posts and views flat, chronological comments on a Course or a specific Lesson, visible to enrolled learners and the instructor (FR-28..FR-29); success: an enrolled learner's comment on a lesson is visible to other enrolled learners and the instructor in posting order.
- (capability) CAP-7 Ratings & Reviews — intent: an enrolled Learner leaves one 1-5 star rating with optional written review per Course; the Course detail page shows aggregate rating plus individual reviews (FR-30..FR-31); success: a learner submits exactly one rating/review per course, visible aggregated on the detail page; a repeat attempt shows their existing rating editable, not duplicated.
- (capability) CAP-8 Moderation — intent: the Admin views and soft-deletes (removes) any Comment, Rating/Review, or Course, visible to the content's author as removed (FR-32); success: Admin removes a comment; it disappears for other users while its author sees it as removed, with no automated flagging UI required.
- (capability) CAP-9 Internationalization — intent: the entire platform UI ships in English and Arabic with correct RTL layout, switchable without losing in-progress state or forcing re-login; Course content is authored by the Instructor in one language with no auto-translation (FR-33..FR-34); success: switching language mid-course-builder-edit preserves the unsaved form and skips re-login; RTL renders correctly across outline editor, video controls, and progress bar; code blocks/console stay LTR regardless of page direction.
- (constraint) No paid courses, ever — permanent product principle, not a v1 scoping choice; zero pricing/paid-access surface may exist anywhere, at any time (standing invariant, SM-3, not a one-time milestone).
- (constraint) No advertising, ever — Sanabel does not carry ads to fund itself.
- (constraint) Interactive Code Exercise submissions must run in a sandboxed environment with enforced CPU/memory/time limits and no network egress — launch-blocking security requirement, not a hardening pass added later, given real public traffic at launch.
- (constraint) Video/PDF uploads are capped per Lesson and per Instructor to bound Cloudflare Stream cost exposure (no revenue to offset it); an upload exceeding the cap is rejected at upload time, never silently truncated or accepted-then-billed.
- (constraint) Bilingual English/Arabic with full RTL is a first-class v1 requirement across every UI surface (nav, forms, course-builder outline, video player, progress bar, transactional email, certificate rendering) — not a locale bolt-on; code blocks and the code-exercise console always stay LTR/monospace regardless of page direction.
- (constraint) Moderation is manual-only (Admin/Ahmed) in v1 — no automated filtering or community flagging; accepted as unable to scale past a small userbase.
- (constraint) Modular monolith: one Next.js app over one Postgres DB; each table has exactly one owning module, and cross-module access goes only through that module's exported service layer, never a raw query against another module's schema (architecture AD-1..AD-3).
- (constraint) Soft-delete only, never hard delete, for Course/Module/Lesson/Comment/Rating — by any actor, through any surface — so Enrollment/Progress/Certificate rows are never orphaned (architecture AD-11).
- (constraint) Certificate issuance is a persisted one-time write, unique per Enrollment (DB-enforced), never recomputed live — an already-issued certificate is never retroactively revoked by later course changes (architecture AD-7, AD-13; realizes FR-15).
- (constraint) Database enforces uniqueness, not just application code: one Enrollment per (account, course), one Rating per (account, course), one Certificate per Enrollment (architecture AD-13).
- (constraint) Cloudflare Stream spend-per-active-learner must not grow unbounded as a side effect of chasing enrollment growth; course/instructor-signup quantity must not be optimized at the expense of course quality (SM-C1, SM-C2 guardrails).
- (non-goal) No paid courses, no pricing tiers, no premium course — permanent, not a v1 scoping choice.
- (non-goal) No advertising.
- (non-goal) No mobile app in v1 — web only, responsive; native/PWA is a possible later phase, not committed.
- (non-goal) No donation/payment feature in v1 — possible later addition, explicitly never a gate on access.
- (non-goal) No automated content moderation in v1 — manual admin review only.
- (non-goal) No pre-publish content review queue in v1 — Instructors self-publish; Unlisted visibility is the only pre-public-listing gate.
- (non-goal) No certificate verification portal in v1 — certificates are downloadable files with no public lookup mechanism.
- (non-goal) No content auto-translation — bilingual scope covers platform UI, not machine-translating Instructor content.
- (non-goal) No topics outside software/coding — Category scope stays fixed to coding education.
